Platform Overview

This is a Business-to-Agent Prompt Compiler with integrated Enterprise Compliance Guardrails. It serves as the front door for enterprise IT change: business and IT stakeholders can submit an idea, a problem, a regulation, a process issue, a call recording, a screenshot, a video, an audio note, or a technical repository, and the platform compiles it into execution-ready, secure initialization scripts for autonomous coding agents (like Devin).

Two Entry Points

Business Mode — Start from a business need

For business stakeholders, product owners, transformation teams and CIO offices.

Example inputs:

  • "We need to improve customer onboarding"
  • "We must comply with a new regulation"
  • "The current approval process is too slow"
  • "We want to launch a new digital service"
  • "Customers are dropping off during document upload"

IT Mode — Set Execution Boundaries

For application owners, architects, engineering teams and IT demand managers. Define the guardrails AI agents must respect.

Boundary-setting features:

  • Define allowed repositories and access scopes
  • Set mandatory architectural patterns (e.g., Event-driven, Microservices)
  • Establish risk thresholds and CI/CD gates
  • Inject enterprise tech-stack constraints

Output: Requirement Intelligence Pack (10 Sections)

1. Executive Summary

Business objective, current problem, expected outcome, impacted stakeholders, value hypothesis, urgency/deadline, confidence score.

2. Business Requirements

Business capabilities impacted, process changes needed, user groups affected, success metrics, business rules, open questions.

3. Functional Requirements

Requirement ID, description, user role, priority, rationale, acceptance criteria.

4. Enterprise Guardrails (NEW - Shift-Left Security)

Non-negotiable compliance constraints automatically injected from GDPR, DORA, and internal security policies. Each guardrail includes a trigger, enforcement action, regulatory standard reference, and severity level.

5. Technical Requirements

Systems impacted, APIs/integrations, data implications, architecture considerations, non-functional requirements, security and compliance constraints.

6. User Stories

Format: "As a [user], I want [capability], so that [business outcome]." Each includes priority, acceptance criteria, dependencies, risks, suggested test cases.

7. Risk & Dependency Map

Technical dependencies, business dependencies, compliance risks, delivery risks, data risks, operational risks.

8. Delivery Plan

Recommended implementation path, MVP scope, out-of-scope items, estimated complexity, delivery phases, test strategy, rollback considerations.

9. Compiled Devin Initialization Script (NEW - Primary Output)

The primary export: a compiled Agent_Init_Script.md containing Context & Goal, Strict Boundaries (injected from compliance), and Acceptance Criteria as Executable Tests.

10. Evidence Analysis

Extracted insights from uploaded audio, video, images, documents, and repositories.

# Agent_Init_Script.md — Compiled by Requirement Intelligence Portal ## Context & Goal You are implementing improvements to a digital customer onboarding application (Spring Boot 3.3 + React 18 + PostgreSQL 16). Business Goal: Reduce customer onboarding drop-off from 35% to under 10%, cut average approval time from 3 days to under 4 hours, and ensure full regulatory compliance for upcoming Q4 2026 audit. Repository: https://github.com/sartan83/online-banking-application (branch: main) Scope: Phase 1 — Foundation: Document upload redesign, application resume capability, status tracking API, basic audit logging. ## Strict Boundaries (Injected from Compliance) 1. SECURITY: All customer documents MUST be encrypted at rest using AES-256 and in transit using TLS 1.3. No exceptions. 2. SECURITY: PII data MUST be masked in all application logs, error outputs, and audit trails. 3. COMPLIANCE (GDPR Art.32): Implement role-based access control for all endpoints handling personal data. 4. COMPLIANCE (DORA): The document upload service and status API MUST have automated failover. Target: 99.99% availability. 5. COMPLIANCE (GDPR Art.22): Auto-approval routing MUST log the decision rationale. High-risk applications (>$50K) MUST require human review. 6. ARCHITECTURE: Document upload service MUST be a separate microservice with independent horizontal scaling. 7. ARCHITECTURE: Audit trail MUST use append-only storage. Records are immutable once written. 8. DATA: Database migrations MUST be backward-compatible. Use expand-contract pattern. 9. DATA: Implement data retention policy: 7-year retention for audit records, 30-day expiry for incomplete applications. 10. TESTING: All routing logic MUST have >95% unit test coverage. Integration tests required for document upload pipeline. ## Acceptance Criteria as Executable Tests - test("customer can resume incomplete application"): Start onboarding, close browser, return after 1 hour — verify all previously entered data is preserved. - test("document upload works on mobile"): Upload passport photo via iOS Safari and Android Chrome — verify file validation completes in <3s. - test("real-time status tracking"): Submit application, verify status page shows current step and estimated completion time. - test("risk-based routing"): Submit low-risk application — verify auto-advance within 1 hour. Submit high-risk ($50K+) — verify manual review queue. - test("SLA monitoring"): Create application approaching SLA threshold — verify yellow warning at 80%, red alert at 100%. - test("audit trail immutability"): Create approval decision, attempt to modify via direct DB — verify record is immutable. - test("PII masking in logs"): Trigger document upload error, inspect logs — verify no PII in plain text. - test("encryption at rest"): Upload customer document, inspect DB — verify content is encrypted (AES-256). - test("GDPR right to erasure"): Request data deletion — verify personal data removed, audit entry created. - test("backward-compatible migration"): Apply migration, verify existing functionality, rollback, verify no data loss.
